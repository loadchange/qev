# Qev-0.8B model card

This document records the original general decision checkpoint, `qev-0.8b[-mlx]`. The new terminal Snake checkpoints are `qev-snake-0.8b[-mlx]`; see the [specialized model report](SNAKE_MODEL.md) for training, retained capabilities and comparisons.

Qev adds a separate language LoRA adapter and candidate pointer head to the complete `Qwen/Qwen3.5-0.8B` multimodal foundation for text-conditioned `choice`, `noul` and `score` decisions. It preserves the foundation's original text, image and video understanding and language generation paths. This is a small supervised learning experiment. Jev / TypeSafe compatibility describes interfaces and output types, not an official relationship, reproduction of private weights or equivalent quality.

The tables on this page are generated by `scripts/update_model_card.py` from actual artifacts. Missing reports are marked “Pending validation”; unit tests and audits of untrained models do not replace evaluation of the trained checkpoint.

## Foundation, architecture and generation

- The foundation is pinned to `Qwen/Qwen3.5-0.8B@2fc06364715b967f1860aea9cf38778875588b17`, instantiated as the full `Qwen3_5ForConditionalGeneration`.
- The original visual encoder, image/video processor, language model, vocabulary and LM head are retained. Its 24 language layers mix GatedDeltaNet and full attention, with a language hidden dimension of 1024.
- Language projection layers receive LoRA with rank 16, alpha 32 and dropout 0.05. Hidden vectors at candidate ends and the decision position are each projected to 256 dimensions; their dot products produce candidate logits. Only LoRA and the pointer head are trained for decisions; all original parameters stay frozen.
- `choice` returns the highest-probability candidate; `noul` returns the probability of yes; `score` returns the probability-weighted expectation of ordered candidate levels. JSON is constructed programmatically, without free-form generation followed by parsing.
- Each question is encoded independently. Ordinary attention masks cannot isolate GatedDeltaNet's recurrent and convolutional states, so Qev does not use Kev's shared-prefix branching for multiple questions or claim to compute the state only once for multiple questions.

**Native generation explicitly disables decision LoRA, preserving the original weight path.** Adapters are stored separately and never merged into the foundation; their state is restored after generation. SHA-256 hashes of frozen parameters before and after training verify foundation integrity. The MLX export also retains the complete visual/language model and switchable adapters. Freezing weights and disabling adapters preserve the original computation path; framework, precision, operator and generation settings can still produce numerical or token differences. Actual comparisons appear below.

All decision supervision in this run was textual. Accepting image/video inputs and producing finite probabilities demonstrates that multimodal input processing works; **multimodal decision accuracy has not been evaluated for this checkpoint**; a later zero-shot probe of the Snake checkpoint is summarized in the [backbone experiment](../experiments/diffusion/README.md). Native generation from image/video inputs is inherited from Qwen and does not establish that the new pointer head has learned visual decisions of equivalent quality. The temperature fitted on text is not applied to multimodal decisions, which use `T=1`.

## Training and artifacts

The objective is supervised cross-entropy over candidate labels, without reinforcement learning, Jev distillation or JEPA latent prediction. Training uses AdamW, weight decay 0.01, 10% warmup followed by cosine decay, gradient clipping at 1 and seed 42, for 2 epochs. Each microbatch contains 4 questions with 4 accumulation steps, usually giving an effective batch of 16; the final partial batch is normalized by its actual question count.

The text sequence budget is 1024 tokens and the state budget is 384 tokens. Candidates or instructions that do not fit raise an explicit error; options are never silently removed. CUDA uses FP32 master weights, BF16 autocast and an FP32 pointer head, also used for post-training evaluation. Development data is excluded from gradient updates; a single temperature is selected using NLL on calibration only.

## Measured evaluation

The main development metrics are candidate argmax accuracy, NLL, Brier, ECE and Score MAE. Questions receive equal weight; a multi-question request contributes multiple samples. Brier is the sum of squared errors across all candidates in each question, and ECE uses 10 equal-width bins of maximum probability. Score MAE uses zero-based candidate-level indices, matching the HTTP score scale.

The random-pointer baseline uses LoRA in its initial state and measures the new decision head before training; it does not measure Qwen's native question-answering capability. A scalar temperature does not change candidate argmax. It is fitted to a particular calibration distribution and does not guarantee that confidence equals accuracy in any domain, language or modality. The high-confidence error rate below is the fraction of all questions with maximum probability at least 0.9 and an incorrect prediction.

The default service and `Agent` infer one question at a time (Torch `batch_size=1`, matching MLX), so adding other questions to a request does not change each question's computation shape. Python callers may explicitly increase `batch_size` for throughput, but changes in batching and padding under CUDA BF16 may alter probabilities. Training and offline evaluation above still used batch 4; per-question service outputs can differ slightly and should not be assumed identical across every invocation mode.

## Intended use and limitations

Suitable uses include local experiments in routing, classification, rule judgments and ordered scoring with explicit candidates. The model always distributes probability over the supplied set and cannot automatically detect a missing correct option; none reliability depends on training coverage. Candidate order, phrasing, length, domain shifts and extreme class imbalance may affect results. Evaluate independently on the intended distribution.

Native generation uses non-streaming `POST /v1/chat/completions`; structured decisions use `POST /v1/systemone`. HTTP multimodal inputs support embedded PNG/JPEG/WebP images and explicitly sampled video frames, without reading local paths, fetching remote URLs or accepting raw MP4. See the [API documentation](API.md) for resource budgets, request structure, confidence definitions and model aliases. The compatibility alias `jev-latest` does not switch to a Jev model; Score confidence is an approximation defined by this project and does not claim to reproduce TypeSafe's unpublished algorithm.
